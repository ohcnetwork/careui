# Plan 003: Fix ESLint Configuration to Exclude Generated Assets

**Baseline Commit**: 8c23b59
**Category**: Tooling / DX
**Effort**: S (~10 min)
**Risk**: Low — config-only change, no code modifications
**Confidence**: HIGH

---

## Summary

ESLint is linting the `ds-bundle/` directory, which contains vendored/generated TypeScript assets that aren't source code. This produces 10+ false-positive errors and warnings that obscure real lint violations:

- `ds-bundle/_ds_bundle.js` — rule definition errors for `react-hooks/exhaustive-deps`, `@typescript-eslint/no-explicit-any`
- `ds-bundle/*.d.ts` — type definition warnings

The ESLint config already has a pattern that ignores `.agents/` directory but does not exclude `ds-bundle/`. This is simple to fix: add `ds-bundle/**` to the global ignores.

---

## Why This Matters

- **Noise reduction**: Developers and CI can focus on real lint errors
- **Process health**: `pnpm lint` output is currently unreadable; fixing this makes the command useful
- **CI reliability**: Prevents lint failures in CI caused by asset-generation side effects
- **DX**: Makes linting part of normal development workflow instead of something to ignore

---

## Changes Required

### Change 1: Update eslint.config.js to ignore ds-bundle/

**File**: `eslint.config.js`
**Current**:
```javascript
export default defineConfig([
  globalIgnores(['dist', '.agents/**']),
  {
    files: ['**/*.{ts,tsx}'],
    // ... rules
  },
])
```

**New**:
```javascript
export default defineConfig([
  globalIgnores(['dist', '.agents/**', 'ds-bundle/**', 'public/registry/**']),
  {
    files: ['**/*.{ts,tsx}'],
    // ... rules
  },
])
```

**Rationale**:
- `ds-bundle/**` — generated assets, not source code
- `public/registry/**` — generated registry JSON files, not source code (optional but recommended)

**Note**: Keep existing ignores (`dist`, `.agents/**`) as-is.
